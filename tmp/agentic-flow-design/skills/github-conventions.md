# GitHub Conventions

## Milestones

Use one milestone per spec or deliverable.

Milestone should contain:

- short summary
- link to canonical spec doc
- owner
- target outcome
- status summary if useful

Do not treat milestone text as the only spec.

## Issues

Use one issue per scoped executable task.

Issue should contain:

- task goal
- scope
- dependencies
- acceptance criteria
- verification expectation
- linked milestone
- role owner

## Project States

Recommended states:

- Inbox
- Shaping
- Ready
- In Progress
- In Review
- Blocked
- Done

## Labels

Recommended labels:

- `role:strategist`
- `role:tech-lead`
- `role:builder`
- `role:validator`
- `type:feature`
- `type:bug`
- `type:debt`
- `risk:high`
- `status:blocked`
- `security`

## Comments

Use issue comments for:

- agent handoffs
- findings
- blocker notes
- approval notes
- deferred follow-up decisions

Use PR comments for code-specific findings and review discussion.
