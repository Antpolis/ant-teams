# Protect Working Context

## Trigger

Use when an agent must coordinate many sources, long outputs, parallel investigations, or work likely to span context compaction or a session handoff. A short result needed immediately does not need an extra summary or delegate.

## Rule

Keep the working context focused on the decisions and evidence needed next. Inspect relevant sources selectively and use bounded delegates or accessible artifacts for bulk when that reduces load. Preserve the rationale and exact evidence needed to verify a conclusion; a short summary is not a substitute for checking consequential claims.

## Apply

- Narrow searches and reads to the question. Route large independent investigations to a delegate only when useful; request a concise conclusion, uncertainty, and precise evidence pointers.
- Before dependent handoffs, pass the actual accepted decisions, user corrections, constraints, unresolved questions, and source links. Follow the existing context-relay procedure for the required session note and record boundaries.
- Before relaying a result as a completed prerequisite, wait for the responsible work to finish and inspect its relevant result and evidence. Mark progress, interruptions, or incomplete verification as such; a handoff message alone does not prove completion. Relay unresolved status and the next action rather than inventing a conclusion.
- Before compaction or resumption, capture current state, active work, decisions, risks, and next actions in the existing appropriate working record. For managed delivery GitHub remains authoritative; a summary or session note does not create approval or replace it.
- If an artifact or note is inaccessible, relay the necessary content through an available channel. Never assume sibling agents share conversation history or filesystem access.

## Boundaries and examples

- A large test log can stay in an accessible artifact while the coordinator receives the failed checks, relevant excerpts, and location. Inspect the evidence before making a consequential claim.
- For a short three-line error, read it directly; creating a delegate and a separate summary would add friction without saving meaningful context.
- Do not discard material qualifiers, secrets safeguards, or required source evidence in the name of brevity. This principle does not start a workflow or require a GitHub artifact.
